## Verified boundary and compatibility

Verified on 2026-09-30 with Node 24.19.0, CAP 10.1.1, agents 0.9.7, MCP 1.5.0 and the course SQLite development fixture. Pinning the agents package does not pin every transitive dependency; preserve the reviewed application lockfile and rerun integration checks after dependency changes.

The service requires the existing IncidentReader role. At 10-preview there is no mutation tool. At 11-preview-action the manager can request raiseUrgency through the assistant, with @agent.hitl approval and the existing role/business checks. A reader cannot execute it. There is no row-level `where` restriction: readers can read every active incident in the five-field projection, including closed incidents. Drafts, conversation messages, other business partner details and managed audit fields are not exposed.

The published plugin defaults to connecting agents to other services. The recipe therefore uses `@agent.connect: 'none'`. This exact setting is **UNVERIFIED against cds-mcp documentation**: current search results did not document it. It is verified against the installed 0.9.7 source (`srv/handlers/index.js`) and runtime: the read-stage tool list is exactly `describe`, `query`; the action stage adds the annotated action subject to manager access and approval. Do not substitute the unverified `@agent.tools: 'local'` spelling or remove the setting. Revalidate before upgrading.

The maintainer verifier uses the plugin's internal `buildTools` event to inspect the real tool list. That internal API and the Node mock configuration are likewise **UNVERIFIED against cds-mcp documentation**, and are source/runtime verified only for the pinned package. They are test instrumentation, not the learner application's implementation contract.
