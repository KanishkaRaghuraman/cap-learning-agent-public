# Course safeguards

AGENTS.md owns the single-chat interaction; course/BUILDER.md supplies internal implementation guidance. Before every learner-authored activity explain the activity, provide **For example:** and a short natural prompt, then accept the learner’s wording. Internal recipes are not copied into learner prompts. Routine setup, terminal instructions, permissions and preview confirmation use direct instructions without copied example prompts.

Teach before action and explain observed results afterwards. One bounded request includes its necessary verification/repairs. Questions alone do not authorize edits; optional reflection is not an exam. No manual-code/log/UUID transcription burden. One app writer, preserved data and recorded evidence.

Full Java/Node.js0–12 and short Node.js0–3 reuse canonical extensions. Foundation is prerequisites plus bundled-starter installation, not ten hidden phases. Prepared does not mean studied. Required final12 uses native application MCP in both runtimes; preserve the Java app. It needs business query, learner follow-up and fresh readback, not a new backend or key. Optional Node.js embedding needs explicit choice, supported API key, real provider/tool/UI evidence; mock or fluent answers do not prove it. Java optional embedding remains unsupported by this recipe.

Current MCP documentation/model evidence and actual API results remain mandatory. Use only current lesson-specific checks: incremental UI construction has its build/lint/manifest checks; Explore setup and MCP extensions do not require browser automation or exhaustive maintainer regressions. Failed or unavailable checks remain pending. Native config reload is verified in the actual client. Never invent documentation, APIs, output or success.

New short setup uses prerequisite evidence and starter-readiness.json, with human preview separate. Legacy foundation snapshots do not gate it or later extension changes. Resume/migration preserve pending confirmation and never replay a mutation. Credentials remain outside course state and evidence.

Live raiseUrgency requires exact target/action approval once, actual native invocation, independent persistence/UI readback and readback of the result. Do not require or offer exhaustive regression after the learner action. Cancellation leaves data unchanged. Chat confirmation is not server-managed approval. The embedded assistant has no route around its read-only interface.

Verify process ownership before stopping any browser/server/helper. Preserve global configuration and other sessions. Report finite tested coverage precisely. The user will perform learner-flow testing; structural/source checks cannot be reported as native success.

Explore MCP and agents selection starts routine setup immediately. The learner owns the preview terminal; explain in-memory data reset before asking them to restart. Native config readiness requires calls from the actual changed client; direct HTTP is diagnostic only. Required human preview stays pending until reported. Use neutral choice names and route-local numbers in conversation, never internal source labels.
