# Extension troubleshooting: restore the lesson, then return control

Follow root `AGENTS.md` and `course/BUILDER.md`. Reading this guide, existing local connection instructions and redacted error evidence is already part of teaching: do it immediately, without asking permission just to read. If required MCP grounding is unavailable, do not provide CAP installation/code instructions from a recipe as a fallback. Limit the response to connection diagnosis and keep the implementation step blocked. Save the current step, exact command/tool name, exit/status and error without credentials. The accepted bounded learner request includes repairs and rechecks within that task; perform these without another permission loop. Unrelated rewrites remain out of scope. Diagnose one cause, make the smallest documented change, rerun the failed check and affected regression checks. Never mark a blocked case passed.

If one diagnosed retry fails, save **BLOCKED** with the exact remaining condition and next investigation. The instructor must not loop installs, substitute a different connector, skip a verification or invent success. A maintainer can investigate separately; the learner's checkpoint stays at the last verified step.

## When the learner is stuck on the concept

Ask which part is unclear. Use one actual incident and one explanation: the client chooses a query, the service returns data; or the client requests an action, CAP validates stored state. Do not require a prediction. Offer at most one optional reflection per lesson and honor skip immediately. The builder performs the current implementation and checks; the learner can explore the result. Do not turn troubleshooting into autonomous course completion.
